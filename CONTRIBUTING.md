# Contributing

Contributions should add tested engineering value, safe failure practice, or clearer production reasoning.

1. Fork the repository and create a focused branch.
2. Keep the default path local and cloud-free.
3. Add or update schema/policy validation with manifest changes.
4. Document objective, expected state, evidence, verification, recovery and cleanup.
5. Run `./scripts/check.sh`.
6. Open a pull request using the template.

Do not include kubeconfig content, tokens, cloud credentials, account IDs, employer/customer information, internal URLs, production logs, or proprietary manifests.
